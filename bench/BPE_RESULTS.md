# ByteLevel BPE throughput and optimization (2026-09-28)

This measures the new compiled BPE path using the tokenizer from
`FacebookAI/roberta-base` at commit `e2da8e2f811d1448a5b465c236feacd80ffbac7b`
(tokenizer JSON SHA-256 `847bbeab6174d66a88898f729d52fa8d355fafe1bea101cf960dd404581df70e`).
The embedding weights are **synthetic**, generated by `make_bpe_fixture.py`:
50,265 vocabulary IDs, 1,024 float32 dimensions for dense, and one scalar per
ID for sparse. These are throughput fixtures, not trained encoders.

The host was an Intel Core i9-13900HX on Linux, with 8 performance cores, 16
efficiency cores, and 32 logical CPUs. The generated programs were compiled
with `-O3 -march=native`. Input was the same 10,000 GooAQ questions used in
earlier benchmarks (mean 43.38 characters, corpus SHA-256
`b8a280ef9ffa7b4f7b66b320c847b804bfeaff5b363294911ea7422e55203d87`),
repeated 100 times for one million queries per run. Output was binary and
directed to `/dev/null`. Timing includes process startup, stdin reading,
tokenization, embedding, and output writes. Each row is the median of three
timed runs after one warmup.

## Initial implementation

| Mode | CPU set | Dense seconds | Dense QPS | Sparse seconds | Sparse QPS |
| --- | --- | ---: | ---: | ---: | ---: |
| One thread, streaming | `0` | 10.281 | 97,266 | 8.750 | 114,293 |
| 8 workers, batch 4,096 | `0,2,4,6,8,10,12,14` | 2.351 | 425,286 | 2.136 | 468,183 |
| 16 workers, batch 4,096 | `0-31` | 1.382 | **723,604** | 1.752 | **570,912** |

For dense output, four workers at batch 256 reached 286,424 QPS; eight
workers at batch 256 reached 295,940 QPS. With 32 workers at batch 4,096,
dense throughput fell to 578,600 QPS. Of the settings measured, 16 workers
at batch 4,096 was fastest for dense output. Sparse throughput was measured
at one, eight, and 16 workers.

With `--tokens` (token IDs as JSONL, no embedding rows), the BPE executable
reached 111,598 QPS on one core and 517,435 QPS with 16 workers at batch
4,096. The single-core token-only result is close to the end-to-end results,
so tokenization accounts for much of the single-core runtime. The batched
token-only path also pays for JSON formatting on the main thread and is not a
pure tokenizer microbenchmark.

For context, the previously built 1,024-dimensional WordPiece static model
reached 515,027 QPS on one core and 1,912,176 QPS with 16 workers at batch
4,096 when re-run on the same corpus and machine. Its token-only single-core
result was 1,301,471 QPS. The models have different tokenizers, vocabulary
sizes, and weight tables (the BPE dense executable is 199 MiB versus 121 MiB
for WordPiece), so the ratios do not isolate the cost of the BPE algorithm.
The initial BPE implementation used an ICU regex for every input and
repeatedly searched all adjacent pairs after each merge. The next section
measures optimizations to those operations.

## Optimized implementation

The tokenizer now uses a direct offset index to narrow merge lookup by left
token ID and precomputes the token IDs for all 256 ByteLevel symbols. An ASCII
pre-tokenizer handles ASCII text without converting it to ICU strings; the
ICU regex remains for Unicode text. Each pre-token stores its adjacent pair
merge ranks and updates only the neighboring pairs after a merge.

The same benchmark settings gave:

| Mode | Dense before | Dense after | Sparse before | Sparse after |
| --- | ---: | ---: | ---: | ---: |
| One thread, streaming | 97,266 | **230,883** | 114,293 | **321,360** |
| 8 workers, batch 4,096 | 425,286 | **875,214** | 468,183 | **949,314** |
| 16 workers, batch 4,096 | 723,604 | **1,335,697** | 570,912 | **1,168,232** |

All figures are QPS. Single-core dense throughput improved 2.37×; sparse
improved 2.81×. Token-only single-core throughput rose from 111,598 to
324,532 QPS. The optimized dense and sparse binary outputs match the initial
executables byte-for-byte on the first 1,000 GooAQ inputs. The offline test
suite passes, and token IDs match Hugging Face Tokenizers on 3,012 additional
random and edge-case inputs in both streaming and four-worker batch modes.

## Reproduce

Build Icicle, fetch the pinned tokenizer, and make the fixtures:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
curl --fail --location --output build/bench/roberta-tokenizer.json \
  https://huggingface.co/FacebookAI/roberta-base/resolve/e2da8e2f811d1448a5b465c236feacd80ffbac7b/tokenizer.json
python3 bench/make_bpe_fixture.py build/bench/roberta-tokenizer.json \
  build/bench/bpe-roberta-dense --dimension 1024
python3 bench/make_bpe_fixture.py build/bench/roberta-tokenizer.json \
  build/bench/bpe-roberta-sparse --sparse
./build/icicle build fixture --local build/bench/bpe-roberta-dense \
  --output build/embed-bpe-roberta-1024 --cxx ./bench/native-cxx.sh
./build/icicle build fixture --local build/bench/bpe-roberta-sparse \
  --route query --output build/embed-bpe-roberta-sparse --cxx ./bench/native-cxx.sh
```

Example single-core and batched runs (replace the executable path to test
the sparse fixture):

```sh
taskset -c 0 python3 bench/benchmark.py build/embed-bpe-roberta-1024 \
  --questions 10000 --repeat 100 --runs 3 --format binary
taskset -c 0-31 python3 bench/benchmark.py build/embed-bpe-roberta-1024 \
  --questions 10000 --repeat 100 --runs 3 --format binary \
  --threads 16 --batch-size 4096
taskset -c 0 python3 bench/benchmark.py build/embed-bpe-roberta-1024 \
  --questions 10000 --repeat 100 --runs 3 --format jsonl --tokens
```
